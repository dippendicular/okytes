# M11 SDK and developer platform

## Implemented

- Added the `okytes-sdk` embedded facade with typed HTTP, FTP/SFTP, torrent and media entry points, filtering, queue priority, result integrity metadata and bounded graceful shutdown.
- Hardened the authenticated daemon contract with capability and constraint discovery, structured error envelopes and durable 24-hour idempotency records for job, advanced submit and torrent creation.
- Added a lightweight Rust daemon client configuration, opt-in browser capture, structured remote error type and reconnecting bounded events.
- Expanded TypeScript and Python async clients with high-level protocol operations, token providers, retry/backoff, idempotent creation, capability checks and structured errors.
- Added package metadata, declarations/source maps, changelogs, license payloads, examples and buildable Python sdist/wheel configuration.
- Consolidated standalone test infrastructure under `dev-tools/test-suite` and documented owner-specific and full acceptance commands.

## Verification

No test suite was run during this implementation pass at the owner's request. `git diff --check` is the only source check planned for this pass. Rust, TypeScript, Python, generated OpenAPI and package artifacts therefore remain unverified until the documented test sequence runs in an environment with the pinned toolchains.

## Preserved qualification gaps

Earlier M3/M8/M9/M10 platform and release qualification gaps remain open. npm, PyPI and crates.io publication requires repository credentials and an approved tagged release; source and automation do not claim a public package has been published.
